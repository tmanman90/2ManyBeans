## Goal

Upgrade the Chat tab (Professor Ruphus) in three phased tiers on the redesign branch, dev channel only. Phase A (intelligence): chat moves to claude-sonnet-5 with thinking disabled (Haiku fallback pre-first-byte only, thinking param rebuilt per final model, token budgets re-baselined via count_tokens); RUPHUS_KNOWLEDGE + TASTING_KNOWLEDGE join the cached static prompt; the dynamic block gains the user's sanitized first name and active-rotation origin context; the "Scan a bag" chip opens the camera instead of sending text; "Coach my tasting" opens the Tasting Wizard (zero beans: in-character line, then a dedicated onNavigateToTasting prop — the shared handler's falsy no-op stays for BrewTimer); the scanned-bean Guided Tasting button dedupes, saves with a busy state, and hands off; rotation-aware starter prompts ship in Phase A; scan truncation can never render raw marker text; the message renderer is extracted with UUID keys. Phase B (premium): a NEW api/claude-stream.js endpoint streams NDJSON (spike-gated: curl -N transcript proves incremental delivery before any UI work; shared constants incl. the FULL RATE_LIMIT with windowMs live in api/_lib/claudeShared.js; api/claude.js untouched beyond the allowlist entry); the client streams via window.CapacitorWebFetch (CapacitorHttp buffers) with a flagged buffered-transport fallback; tokens render in an isolated StreamingBubble (ref buffer + rAF flush, plain DOM + CSS entrances, role="log" announce-on-commit, composer disabled in flight); marker hold-back never shows partial markers; the conversation persists to users/{uid}/chatSessions/active (rolling 50-message doc, fire-and-forget LWW-once-hydrated full snapshots, hydration-gated, idb mirror unconditional, injectable storage adapter, New chat affordance, additive-only rules deploy); brew answers can emit a RECIPE_CARD marker rendered as an editorial card with Brew + capped Save-to-notes actions. Phase C (depth): a palate summary (level + per-axis tastingScores means, sanitized descriptors) joins the dynamic block; NEEDS_SEARCH two-pass live web answers (marker-only response, pass two replaces pass one, capped visible query, untrusted-data framing, https-only sources footer from groundingChunks). Everything design-bank clean: monochrome + one accent, gradient-free thread, CSS keyframes for entrances, framer only for whileTap/layoutId, reduced-motion gated chrome, Professor Ruphus naming, 44pt targets. PRE-LOOP PRECONDITION: the "Tal" naming hotfix (user-agnostic prompt wording) ships to production BEFORE this loop launches; the loop treats it as landed baseline.

## Definition of Done

The extended verify-chat harness proves: scan chip opens the picker with no sent bubble; a text starter sends; coach-chip spy fires with the first active bean id (and the zero-bean path posts the line + fires onNavigateToTasting); scanned-bean handoff saves exactly once with a busy state and dedupes; rotation-aware starters derive from seeded beans with static fallback; progressive streaming against the stream-mock server (text strictly grows across polls); recipe card renders from a mocked marker with save-state transitions; persistence round-trips through the injectable adapter (resume, trailing-retry, 50-cap, New chat, key uniqueness); reduced-motion pass; zero linear-gradients; zero console errors. verify-stream-parse proves marker hold-back across arbitrary chunk splits, truncation rejection, framing-spoof fixtures, prose-then-NEEDS_SEARCH replacement, and typed pre-stream errors. All prior verify-* gates stay green. The U5 curl -N transcript (multi-timestamp incremental arrival, thinking disabled, usage frame with cache fields) exists as evidence; kill-mid-stream shows upstream abort with usage still logged; shipping in buffered-fallback mode requires the explicit contract flag. The firestore.rules diff is exactly one new chatSessions block, deployed with the fully specified command after a dry-run pre-flight, with denial checks and the post-deploy smoke check recorded in the loop log. The per-tier evidence gate passes tier A/B on simulator frames (thinking loader, two stream-in-progress frames with visibly longer text, recipe card, dynamic starters, resumed conversation after relaunch, New chat, scan-chip camera prompt) without any tier-C frame; tier C adds search caption + sources footer. Fresh codex passes the pre-briefed rubric. Tal signs off on device (v5), including keyboard-during-stream and background-and-return checks. Dev channel only; no prod deploy or main merge by the loop.

## Scope Guard (do NOT touch)

- PRE-FLIGHT (verify before iterating): the "Tal" naming hotfix is live on production; dry-run of "npx firebase-tools deploy --only firestore:rules --project <VITE_FIREBASE_PROJECT_ID>" succeeds with non-interactive credentials; window.CapacitorWebFetch exists in the native bridge.
- Do NOT touch useNativeKeyboard, input-bar positioning, safe-area math, or scroll/keyboard interplay code.
- Do NOT change the reactToTastingStep call shape, paywall/demo gating semantics, or any non-claude proxy (api/gemini.js, api/openai.js, api/aiden.js) beyond the U11 CLIENT helper in src/lib/gemini.js.
- api/claude.js changes ONLY: the claude-sonnet-5 allowlist entry and the shared-constants import from api/_lib/claudeShared.js. All streaming lives in api/claude-stream.js.
- firestore.rules is ADDITIVE-ONLY: the diff must be exactly one new chatSessions match block; any edit to an existing block fails the gate; run the post-deploy smoke check (cross-uid bean read still denied) and record it in the loop log.
- Phase ordering is a hard gate: tier B units do not start until Phase A gates pass; tier C not until A+B pass; the U5 streaming spike (curl transcript + disconnect check) passes before ANY client streaming UI is written; shipping buffered-fallback requires the explicit contract flag, surfaced as a first-class outcome.
- CSS keyframes for all entrance/visibility (framer animate is dead in this WKWebView portal); framer only for layoutId/whileTap; no animated backdrop-filter, no mix-blend sheen, no feDisplacement; ambient loops exempt from the 300ms rule.
- The chat thread stays gradient-free (keep the zero-linear-gradient assertion); no GlassButton/glass material in-thread; monochrome + single accent; tabular-nums on all card numbers; "Professor Ruphus" in all user-facing copy.
- Streaming text renders via the isolated StreamingBubble only; never render streamed partials through framer-gated visibility; marker hold-back before display, always.
- Persistence invariants are non-negotiable: hydration-gated Firestore writes, fire-and-forget never-awaited persists, plain LWW once hydrated (NO per-write freshness skip), unconditional idb mirroring, chat key added to cacheClear.
- Overnight evidence frames come from the SIMULATOR (sim-from-vite recipe, CapacitorUpdater autoUpdate off during debugging); the real device is Tal's v5 sign-off. Verify streaming behavior in Playwright WebKit, not Chromium, when engine fidelity matters.
- Dev channel only: no production Vercel deploy (except the pre-loop hotfix, which is NOT the loop's job), no Capgo production channel, no main merge. Dev bundle labels use the -devapp.<ts> convention.
- Do NOT migrate api/gemini.js to @google/genai, add multi-thread chat history, remove the TastingTab legacy block, or add markdown rendering: all explicitly deferred.
