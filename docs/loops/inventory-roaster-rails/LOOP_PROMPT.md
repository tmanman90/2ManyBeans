## Goal

Rebuild the Inventory tab so it reads like App Store "by developer" shelves: scroll vertically through roaster sections (alphabetical, "ROASTER · count" headers), swipe horizontally through that roaster's beans rendered as the flagship card, and tap a card to fly open the trading card via the hero morph. Sealed-bean primary action is "Open into jar" (Brew preserved as secondary). Reuses ShelfCard, BeanDetailCard, and the manual-FLIP morph. Visual/UX only; no Firebase or feature changes; dev channel only.

## Definition of Done

Inventory body is a vertical list of alphabetical roaster sections, each a horizontal scroll-snap rail of flagship ShelfCards; tapping a card morphs open the BeanDetailCard (bag flies, no teleport); the card/detail primary action is "Open into jar" (disabled with an explanation when no empty slot) with Brew/Finish/Learn preserved and no Taste; search still filters across roasters and the no-result + empty states show; open-into-jar / edit / delete / finish still work; reduced-motion disables the morph; `npx vite build` exits 0 and the Inventory Playwright harness renders multi-roaster mock data with rails scrollable, alphabetical order, a working tap-morph, and zero console errors; codex review is clean against the rubric; and Tal signs off on device that the rails, morph, and open-into-jar feel right.

## Verification Criteria (the independent gates)

- `v1-build` (programmatic): run `["npx", "vite", "build", "--logLevel", "error"]`, expect `exit_zero`
- `v2-harness` (programmatic): run `["node", "scripts/verify-inventory.mjs"]`, expect `exit_zero`
- `v3-review` (judge via codex): Adversarially review the Inventory-rails diff. FAIL if: roaster sections are not alphabetical or the "ROASTER · count" header/eyebrow is missing or count is not tabular-nums (R1); a roaster's beans are not in a horizontal scroll-snap rail of ShelfCards (R2); the action footer removed Brew from sealed beans, dropped Finish/Learn, or added Taste, or "Open into jar" is not primary / is a dead button when no empty slot exists (R3, R5); tapping a card does not open BeanDetailCard via the morph, or the morph is not transform/opacity-only (R4, R8); search/no-result/empty states or the open-into-jar / edit / delete / finish handlers regressed (R6, R7); the reduced-motion gate is missing (R8); design-bank violations appear — more than one accent, heavy/glow shadows, non-hairline dividers, missing tabular-nums, motion >300ms or not ease-out (R9); or the diff touches Firebase reads/writes, the bean data model, statuses, other tabs, or onboarding (R10). Also FAIL if two BeanDetailHost instances can mount at once. PASS only when rails are alphabetical scroll-snap, actions are correct + non-regressing, the morph is reused cleanly, and the diff is scope- and design-clean.
- `v4-human` (human): On the dev app (device): scroll Inventory vertically through alphabetical roaster sections, swipe a roaster's rail horizontally, tap a bean and confirm it flies open via the morph, use "Open into jar" to move a sealed bean into rotation, and confirm search still works — proving R1, R2, R4, R5 and the overall feel.
