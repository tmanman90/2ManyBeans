## Goal

Turn the guided tasting into an intelligent, reactive, tap-first wizard where Professor Ruphus predicts what THIS specific bean should taste like (origin × process × roast × altitude), coaches the user through the full Hoffmann sensory arc (Smell incl. break-the-crust, First sip incl. slurp + taste-warm, Acidity, Sweetness, Body, Flavor, Finish, Balance) to find it, reacts and recalibrates, and develops the user's palate over time (texture-first → flavor-naming unlock, derived from history). Tap-first (axis sliders + gated flavor-wheel chips that feed the REAL taste-fingerprint) with free-text + LLM understanding kept; a confident-but-celebratory Ruphus using existing mascot assets; an end-of-session reveal calibrating found- vs-expected/bag. Deterministic core works with no live AI; the LLM coaching is additive. No Firebase / tasting-data-model / extraction-output-shape change; manual entry preserved; comparative two-bean is Phase 3 (NOT built); Higgsfield new-asset generation is a separate track (NOT in this run). Dev channel only.

## Definition of Done

The guided-tasting CTA opens a card-based wizard that walks the full Hoffmann arc one attribute per screen (Smell with a break-the-crust cue, First sip with slurp + taste-warm cues, Acidity, Sweetness, Body, Flavor, Finish, Balance — Flavor and Balance both present); for the selected bean Ruphus shows a structured EXPECTED profile derived from origin × process × roast × altitude and coaches the user to find it, reacting/ recalibrating per step; axis steps use a slider with novice glossary labels and flavor naming uses gated flavor-wheel chips (Tier 1→2→3, Tier-3 gated by a palate level derived from tasting history), with a free-text field always available and understood by the additive LLM layer; the slider values feed the 6-axis tastingScores directly so the FlavorRadar builds live and real; a reveal screen compares what the user found vs the bag/expected then saves a tasting in the EXISTING record shape via the existing addTasting; a "your palate" surface reflects progression; manual entry still works and existing tastings/journal/Flavor Card are unaffected; Ruphus reactions use existing mascot assets; motion is transform/opacity-only and reduced-motion gated and the iOS keyboard/safe-area is correct on the free-text step; no Firebase/data-model/extraction-shape change and the deterministic core works without live AI; `npx vite build` exits 0; the wizard Playwright harness drives the deterministic flow end-to-end (full spine advances, slider→scores + radar grows, chips gate by level, expected profile + reveal render, manual entry opens, reduced-motion, zero console errors); verify-tasting and verify-archive/inventory/morph/chat still PASS; codex review is clean against the rubric; and Tal signs off on device that a full guided tasting feels like a real pro mentor and is fun + beautiful.

## Scope Guard (do NOT touch)

- Do NOT change Firebase, the tasting/bean data model, or the AI extraction OUTPUT shape (the 6-axis tastingScores + tasting fields). The wizard writes a tasting via the existing addTasting in the existing shape.
- Do NOT remove free-text input or the LLM understanding; the LLM coaching extends claude.js additively and must NOT gate the wizard (deterministic core works without live AI).
- Do NOT build the Phase-3 comparative two-bean mode, and do NOT generate new Higgsfield assets (reuse existing Ruphus mascot assets for reactions).
- Do NOT lose manual tasting entry or regress existing tastings / journal / Flavor Card / spider chart.
- Do NOT add new Firebase fields for progression (derive palate level from existing tasting history); do not animate non-transform/opacity properties or skip reduced-motion; do not deploy to production or merge to main (dev channel only).
