## NEEDS EYES

- [architecture-strategist] grindOffset in getDeviceAdjustedGrindStart() is applied in raw grinder units instead of converting through microns. Chemex offset +2 means +140 microns on Ode Gen 2, but only +10.4 microns on JX-Pro (13.5x too small) and +50 microns on Comandante (2.8x too small). Non-Ode users get nearly identical grind starts across all devices, defeating device-specific adjustment. Fix: convert offset to microns first (offset * 70), then divide by target grinder's perStep from GRINDER_MICRON_SCALES.
- [cross-phase review] BrewMethodMenu shows 5 device options but all call the same handler with no device key. Tapping "Chemex" generates a recipe for whatever device the user set in Settings (e.g. V60), not the one they tapped. Either pass the device key for per-brew selection, or simplify the menu to a single "Manual Brew" row.
- [cross-phase review] roasterStyle dropdown in EditBeanModal writes to Firestore but is never consumed. All 3 call sites for getProfileForRoaster() pass only roasterName, never the bean object. The roasterStyle/roastLevel fallback paths (roasterProfiles.js lines 159-177) are unreachable. Wire the bean param through, or remove the dropdown.

## What got built

Users can now choose from 5 device-specific manual brew methods (V60, Kalita Wave, Chemex, Aeropress, French Press) instead of one generic "Hand Brew." Each device generates a tailored recipe with device-specific grind offsets, techniques, ratio/temp ranges, and post-generation enforcement rules. Aiden grind recommendations translate to any supported grinder via a micron intermediary (Ode Gen 2, Opus, Comandante C40, 1Zpresso JX-Pro, Baratza Encore ESP, Virtuoso+). The roaster database expanded from 14 to 60+ with fuzzy matching, aliases, and 5 style categories. Archived beans now show their saved brew recipes.

## Final /ce:review findings

**Security Sentinel:**
- No P1 findings. Existing sanitization, Firestore rules, and React XSS protections are intact.
- P2: Device key and grinder key from Firestore preferences are not validated against known values before use in useHandBrew.js. Unlike claude.js which has validateBrewMethod()/validateGrinderKey(), the handbrew path passes raw preference values through. Falls back safely to v60/Ode Gen 2, but stores arbitrary strings on bean docs if Firestore is tampered. Low exploitability given auth-gated Firestore.
- P2: roasterStyle written to Firestore without server-side validation (UI constrains to valid keys, but modified client could write anything). Safe fallback behavior.
- P3: Legacy migration .catch(() => {}) silently swallows errors. Functionally safe due to in-memory normalization.
- P3: Fuzzy matching at score >= 60 could produce false positives for short common words used as roaster names (Heart, Ruby, Temple). Impact limited to incorrect peak window advice.

**Performance Oracle:**
- No runtime performance concerns. All computation is client-side, event-driven, bounded by small static datasets.
- P2: Recipe cache stores one recipe per bean (last device wins). Switching devices loses the prior recipe and forces a new API call. Consider keyed storage (bean.handBrewRecipes[device]) in a follow-up.
- P3: Dead exports grinderSettingToMicrons() and isManualBrewMethod() add maintenance burden. Tree-shaken from production bundle.

**Code Simplicity Reviewer:**
- P2: ~37 specialty-light roasters in ROASTER_STYLE_MAP map to the same values as DEFAULT_PROFILE. Only roasters with non-default categories (Nordic, Medium, Dark, Extended Rest) change behavior. Could trim to ~20 entries with zero behavioral change.
- P2: IMMERSION_OVERRIDES table could be folded into BREW_DEVICE_CONFIGS directly, eliminating one layer of indirection.
- P3: category field on BREW_METHODS entries, BREW_DEVICE_CONFIGS export, buildTechniqueBlock blocks object are unused externally.

**Architecture Strategist:**
- P1: grindOffset applied in raw grinder units, not microns. Device-specific grind shifts (Chemex +2, Aeropress -1) are correct for Ode Gen 2 but negligible for JX-Pro (5.2 microns/step) and small for Comandante (25 microns/step). The offset should be converted: nativeOffset = (offset * 70) / targetGrinderPerStep.
- P2: repairHandBrewRecipe rule 7 warns about maxBrewTime violation but does not clamp. Every other repair rule actively mutates the recipe. Inconsistency: comment says "Clamp max brew time per device" but only logs.
- P2: Fuzzy match beats explicit user roasterStyle in the resolution chain. If "Heartland Coffee" fuzzy-matches "Heart" (score 80), the user's manually-set roasterStyle is ignored. Move roasterStyle check above fuzzy match if user override should take priority.
- P3: R07Preferences defines its own BREW_OPTIONS array instead of importing BREW_DEVICES. Adding a new device requires updating both files.
- P3: QuickRecipeFlow still uses 'handbrew' as activeMethod literal instead of the actual device key.
