## What got built

Two tightly-coupled fixes on the hand-brew recipe modal, both surfaced on the first real-device test of the timer feature from the prior rip-it run.

**(1) Ratio card fix.** The RATIO param card now renders with a `Scale` icon and matches the layout of COFFEE / WATER cards. One-line fix at `HandBrewModal.jsx:100`.

**(2) Interactive coffee dose stepper.** The COFFEE param card is now an interactive `DoseStepperCard` with `–` and `+` buttons flanking the gram value. Tap adjusts ±1g, hold repeats at 500ms/120ms cadence, haptic every 5 ticks (picker-wheel detent), boundary bump at 10g / 40g limits. Changing the dose rescales water total and every step's `waterTotal` proportionally in-place. The BrewTimer reads the scaled recipe so step pills show the right numbers. Per-bean persistence via `handBrewRecipe.userCoffeeGrams`; regenerate resets the override. Range 10-40g, whole grams only, no sub-gram UI.

The pristine AI-generated recipe is never mutated — all scaled values are computed at render time via a pure `scaleRecipeForDose()` helper. This makes reset-on-regenerate trivial and keeps the recipe document addressable forever.

## Implementation log (single-shot mode)

### Phase 0: Helpers + Ratio Icon
- Created `recipeScaling.js`. Tested inline via `/tmp/test-scaling.mjs`: **38/38 pass** (14 parseRatioDivisor cases including range strings + garbage, 24 scaleRecipeForDose cases including happy path, fractional, range ratios, unparseable, empty steps, zero/negative/NaN dose, non-mutation).
- Created `useRepeatPress.js` with pointer events, latest-ref pattern (single combined ref to avoid thrashing), one-shot boundary.
- Added `Scale` icon import to HandBrewModal, passed `icon={Scale}` to the RATIO ParamCard.

### Phase 1: Stepper UI + Lifted Persistence + BrewTimer Integration
- Created `DoseStepperCard.jsx` matching `ParamCard` visual tokens exactly.
- Added iOS callout suppression on the stepper buttons (full CSS combo including `WebkitTouchCallout: 'none'`) plus `aria-hidden` wrapper on the `Minus`/`Plus` glyphs to defeat the iOS 17.4+ loupe.
- Rewired `HandBrewModal` to take controlled props (`userCoffeeGrams`, `onCoffeeGramsChange`, `onPersistDose`), derive `displayRecipe` via `useMemo(scaleRecipeForDose(recipe, effectiveDose))`, pass `displayRecipe` to the step timeline AND to `BrewTimer`. Persistence fires on modal close + Start Brew press via `persistIfChanged()`.
- Lifted state into `useHandBrew.js` (not each call site) so all 4 HandBrewModal consumers get it via one hook extension. Hook exposes `userCoffeeGrams`, `setUserCoffeeGrams`, `persistDose`. Hydration effect fires on every non-null recipe identity change.
- R10 plumbing: `QuickRecipeFlow.handleAutoSave` + `handleSave` merge `handBrew.userCoffeeGrams` into `beanData.handBrewRecipe` before writing to Firestore. This was the one real codebase deviation the deepen-plan audit flagged.

### Fix-retry cycles

**Cycle 1 (Codex review #1 after Phase 0 + Phase 1 landed):** 2 blockers.

1. **`useRepeatPress` effect thrash.** Deps list included `onTick`/`canTick`/`onBoundary`. DoseStepperCard's `useCallback` handlers close over `dose`, so they get new identities every tick. The effect tore down and rebuilt the timer chain every tick — exact bug I'd tried to prevent. Cadence was not stable.
2. **Boundary haptic spam.** At min/max the interval kept running and fired `haptic.medium()` every 120ms — a buzz, not a bump.

**Fixes:** latest-ref pattern (refs for `onTick`/`canTick`/`onBoundary` updated on every render, effect reads from `refs.current`, deps list now `[pressing, initialDelay, interval]`). One-shot boundary flag (`boundaryFired` local to the effect closure, resets on re-press).

**Cycle 2 (Codex review #2):** 1 new defensive concern.

- **NaN hazard in `DoseStepperCard`.** If `recipe.coffeeGrams` is ever undefined or non-numeric upstream, `Math.max(min, dose - 1)` produces NaN.

**Fix:** `const safeDose = typeof dose === 'number' && Number.isFinite(dose) ? dose : min;` at the top of the component, used everywhere downstream.

**Cycle 3 (Codex review #3):** 1 hypothetical flagged. Reviewer pointed out `min={NaN}` would still produce NaN. **Classified as nitpick** per `blockers.md` — `DoseStepperCard` has exactly one caller which never passes `min`, so the default `10` is always used. No fix applied.

### Final `/ce:review` (3 reviewers in parallel)

**performance-oracle** — one real blocker flagged:
- `-webkit-touch-callout: none` on the universal `*` selector killed the iOS long-press menu on text inputs (`<input>`, `<textarea>` in AddBeanForm, Chat, tasting notes) AND on images (bean product photos, ShareCard). Users actively use that menu to copy/translate/save-image. **Fix applied:** scoped the rule to `button, [role="button"]` only. Still covers the stepper buttons (they're `<button>` elements) but leaves inputs and images alone.
- Everything else nitpick-grade (inline style object GC pressure, useEffect dep narrowing opportunities, etc.).

**code-simplicity-reviewer** — zero blockers, 3 concrete polish items applied:
- Collapsed 3 parallel `useRef`/`useEffect` pairs in useRepeatPress into one combined ref + one deps-less effect.
- Trimmed `STEPPER_GLYPH_STYLE` to just `{ pointerEvents: 'none' }` (load-bearing part only).
- Dropped `useMemo` on `decStyle`/`incStyle` — object spread is cheaper than the memo machinery for 11-field styles.

Kept separate: `parseRatioDivisor` vs `parseTimeString` (different shapes), `DoseStepperCard` vs `ParamCard` (interactive vs static), `persistDose` in hook (closes over bean/updateBean/setter). All justified.

**julik-frontend-races-reviewer** — 1 real blocker + 1 real bug, both fixed:
- **B1: Firestore snapshot race on `persistDose`.** Local merge → await updateBean → snapshot could fire in the middle and stomp the merge. **Fix:** re-assert `setHandBrewRecipe(prev => ({...prev, userCoffeeGrams: newDose}))` AFTER the await resolves, gated on `mountedRef.current`. Stomps any intermediate snapshot churn.
- **N1: Regenerate flash to 10g.** During regenerate, `handBrewRecipe` goes null for a render → hydration effect fired → `userCoffeeGrams` reset to undefined → `safeDose` fell back to `min` (10) → stepper visibly dropped to 10g before the loading spinner took over. Classified as a blocker because it's a user-visible UX bug. **Fix:** guarded the hydration effect with `if (handBrewRecipe == null) return;` so nulls during regenerate don't clear the override. The next non-null recipe hydrates fresh from its own `userCoffeeGrams`.
- Rest were nitpicks or explicit non-concerns (pointer capture absence is intentional; mid-hold unmount cleanup confirmed clean; latest-ref freshness confirmed safe across React batching).
