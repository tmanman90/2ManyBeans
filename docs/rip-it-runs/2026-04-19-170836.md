## Final /ce:review findings
Three parallel reviewers scored the diff against `blockers.md`. One real bug was caught and fixed before the report; remaining notes are nitpicks.

**Race / lifecycle (julik-frontend-races-reviewer)**
- ⚠️ Resolved pre-report: `onError={() => setErroredUrl(bean.photoUrl)}` captured the *current* prop, not the URL that actually failed. Under a re-scan mid-fetch this would have recorded the new URL as errored and shown the SVG even when the new photo was fine. Fixed by reading `e.currentTarget.src` inside the handler.
- URL-as-state pattern confirmed sound: no stale-lock on re-scan, no useEffect reset dance needed.
- Future caveat (not a blocker): if Archive ever goes virtualized, lift `erroredUrl` into a parent Map keyed by bean.id so scroll-off/scroll-on doesn't re-flash broken images.

**Simplicity (code-simplicity-reviewer)**
- Resolved pre-report: stripped the dev-only `console.warn` in the `onError` branch (4 LOC of YAGNI; browser Network tab already surfaces the failure).
- Zero-prop `Wordmark` and the stateful `erroredUrl` are both judged minimal — no speculative props, no dead code.

**Pattern consistency (pattern-recognition-specialist)**
- Resolved pre-report: aligned `alt` text with `BeanCard`'s `${bean.name} bag` convention (was `alt=""`).
- `Wordmark.jsx` matches codebase style (named export, theme import, inline styles, `role="img"` + `aria-label`).
- No em-dashes introduced in new code comments.
- Nit (not applied): `BeanCard` uses a shimmer `onLoad` placeholder that `BeanThumb` does not. Acceptable at 56px; revisit if a larger consumer lands.
