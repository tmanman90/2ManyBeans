## What got built

A full pour-over brew timer for AI-generated hand-brew recipes. Users tap "Start Brew" on a hand-brew recipe, a 3-2-1 countdown fires, then a full-screen SVG ring tracks elapsed time through each step. Heavy haptic at every step transition, success haptic on completion, pause/resume, skip forward, rewind (step clock resets, global clock keeps ticking), screen wake lock (web only for now), close confirmation mid-brew, and a "Start Tasting Session" bridge that pre-selects the bean and opens the AI tasting coach on the Tasting tab. Survives iOS JS suspension during backgrounding via wall-clock `Date.now()` deltas. Does not apply to Aiden recipes (Aiden is automatic).

## Phase log

- **Phase 0 — Recipe Data Hardening**: CLEAN ✅
  - Completion-guard attempts: 1/3
  - Fix-retry cycles: 3/3 (used all three, blockers resolved on the third pass)
  - Codex findings:
    - **Cycle 1 (3 blockers):** (1) `parseTimeString` MM:SS regex too permissive — `"120:00"` parsed as `20:00`, `"1:99"` as `159s`, `"1:234"` as `1:23`; (2) `parsed < lastSeconds` allowed duplicate timestamps through, yielding zero-length steps; (3) `totalBrewTimeSeconds` never cross-checked against last step — a GPT recipe with total `"2:00"` and last step `2:30` would produce a negative final-step duration. All resolved with lookbehind/lookahead anchors + strict inequality + step 6b cross-check.
    - **Cycle 2 (1 new blocker):** malformed range `"2:30-120:00"` fell through to plain matcher and silently parsed as `2:30`. Resolved by adding a preflight that rejects any input where two time-like tokens flank a range separator but the strict range regex failed.
    - **Cycle 3 (1 gap):** preflight only caught cases where the LEFT side was valid M:SS (missed `"120:00-2:30"`, `"2:3-3:00"`). Resolved by broadening the preflight to `/\d+:\d+\s*[-–—]\s*\d+:\d+/`.
    - Final review: all 4 blockers resolved, no new issues, one nitpick (`"2:30-"` dangling dash) left as acceptable.
  - Lessons compounded: `docs/solutions/logic-errors/regex-parser-malformed-structural-fallthrough.md` — regex parsers with priority-ordered fallback chains need preflight checks for structural intent, or they'll silently salvage the valid half of malformed input. Applies to any date/URL/color/time parser.
  - Test coverage: 25/25 inline unit cases for `parseTimeString` including all 4 malformed-range variants.

- **Phase 1 — Core Timer (MVP)**: CLEAN ✅
  - Completion-guard attempts: 1/3
  - Fix-retry cycles: 2/3
  - Codex findings:
    - **Cycle 1 (3 blockers + 1 partial):** (1) `timerSteps` frozen via `useState` — would break on recipe change / regenerate. Fixed: switched to `useMemo(() => buildTimerSteps(recipe), [recipe])`. (2) rAF loop not actually 60fps — effect depended on `stepElapsedMs` which updates every 100ms, so effect was torn down and rebuilt every tick. Fixed: added `readStepMs()` / `readGlobalMs()` useCallbacks that read live from refs, rAF now drives from them with deps `[phase, currentStepDurationMs, stepIndex]`. (3) Step-boundary flicker (stale state painted against new duration). Fixed by (2). (4) TastingTab one-shot consumption cleared the pending flag even if `beans` hadn't loaded yet — lost the handoff. Fixed: retry on beans/hasPro/freeUsage updates, only clear on terminal outcomes.
    - **Cycle 2 (2 new blockers):** (1) Pill `remainingMs` still read stale `stepElapsedMs` state during step transitions — fixed by calling `setStepElapsedMs(0)` before `dispatch NEXT_STEP` so React batches both into one render. (2) `skipForward` / `rewind` while paused used `Date.now()` as step anchor, under-crediting the new step by the time spent paused before the nav action. Fixed with `stepNavAnchor()` helper that returns `pauseStartedAtRef.current` when paused.
    - **Cycle 3:** all blockers resolved, one defensive nitpick applied (`beginRunning` now explicitly nulls `pauseStartedAtRef`).
  - Lessons compounded: two load-bearing patterns captured inline in comments — (a) wall-clock refs over setInterval accumulators as the source of truth, with state only as a 10Hz display cache; (b) refs + useReducer + rAF live-readers = the minimum viable split for smooth animated timers in React 19.

- **Phase 2 — Polish + Tasting Bridge**: CLEAN ✅
  - Completion-guard attempts: 1/3
  - Fix-retry cycles: 1/3
  - Codex findings:
    - **Cycle 1 (1 blocker):** wake lock module had a race — if `acquireWakeLock()` was called twice concurrently (the `phase === 'running'` effect and the visibilitychange listener on foreground), the second sentinel could be clobbered by the first sentinel's stale `release` event. Fixed: (a) early-return if `sentinel` already set, (b) identity-checked release listener (`if (sentinel === next) sentinel = null`), (c) post-await guard releases the loser if a concurrent acquire won the race, (d) `releaseWakeLock` reads into a local before nulling the module var to prevent reentrance issues.
    - **Cycle 2:** blocker resolved, no new issues found.
  - Lessons compounded: identity-checked release listeners are mandatory for any module-scoped resource sentinel that can be acquired concurrently.

## Final /ce:review findings

Three reviewer agents run in parallel:

### performance-oracle
- **Real risk (theoretical under current codebase):** `buildTimerSteps` memo key is the whole `recipe` object. If a parent ever passes a new recipe object reference every render (e.g. from Firestore churn), the rAF loop would tear down and rebuild constantly. **Mitigated:** in this codebase, recipe flows from `useHandBrew`'s internal `useState`, so the reference is stable. Not a current bug. Defensive memoization on primitive keys is deferred — verified stable by code audit.
- **Nitpick (future-regression trap):** `readStepMs` is in the rAF effect deps, but it's a stable `useCallback([])`. If a future edit adds a dependency to that callback, the rAF loop will start thrashing every 100ms. Documented in the comment above the effect. Not a bug now.
- **Nitpick (optimization):** step pills re-render at 10Hz because the "current" pill's countdown text is in the same subtree. Could be fixed with `React.memo(StepPill)` + dedicated subscriber for the current pill's text, or by dropping the ticker to 4Hz. Deferred — n=3-5 pills, modern iPhones handle it trivially.
- **Confirmed no conflict:** the two `visibilitychange` listeners (one in useBrewTimer for state refresh, one in BrewTimer for wake-lock re-acquire) are independent and clean up correctly.

### code-simplicity-reviewer
- All findings nitpick-grade. Notable: the `useReducer` in useBrewTimer is arguably over-engineered for 2-field state (`phase`, `stepIndex`) — two `useState` calls would be ~25 LOC lighter. **Kept** because the reducer cleanly documents the state machine, and the nitpick is aesthetic.
- Applied: dropped the unused `hasActiveWakeLock()` export from `src/lib/wakeLock.js`.
- Declined: dropping the "90 seconds" parseTimeString tier — it's cheap defense against unexpected GPT output, and falling back to `timerReady=false` with no tier in place would force a regeneration where a simple parse would have worked.

### julik-frontend-races-reviewer
- **Applied:** step-boundary ring flash fix. The `useLayoutEffect` on `stepIndex` change now computes the correct first-frame offset from `readStepMs()` + `currentStepDurationMs` instead of blindly snapping to `RING_CIRCUMFERENCE` (empty). Eliminates a one-frame visual glitch where a stale rAF closure could paint "near-empty against old ring color" between the reducer commit and the new effect mount. Same root cause as Performance's finding #2.
- **Confirmed safe:** Countdown haptic promise doesn't touch state after unmount; `handleBrewTimerStartTasting` teardown order is sound (React 19 batches parent setState calls); TastingTab effect deps are safe (no infinite loop); wake lock visibilitychange race is handled by the identity check; `HandBrewModal open && !timerOpen` gate prevents double-visible overlap.
- **Minor cosmetic nit deferred:** final-step countdown fires a light + heavy haptic within the same frame (light from `value=1` timeout, heavy from `value=0` boundary). Not a UX bug, just a slightly muddled feel on that single moment.
