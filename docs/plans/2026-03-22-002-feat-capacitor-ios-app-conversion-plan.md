# feat: Convert PWA to Capacitor iOS App

## Overview

Convert Coffee Hub from a Vercel-hosted PWA into a native iOS app using Capacitor, without losing any features or connections. Simultaneously polish the frontend UX (clean borders, buttons, consistent spacing). The web version must continue working unchanged.

## Problem Statement

The app is a PWA that works well on mobile Safari, but lacks the native feel and App Store distribution. Key pain points: no native camera integration for bean scanning, no haptic feedback, Google Sign-In popup is fragile on iOS, and the app can't be discovered in the App Store. Additionally, some UI elements have inconsistent borders, button styles, and spacing that should be cleaned up for both web and native.

## Proposed Solution

Install Capacitor, configure it for iOS, and adapt the six areas where web-only code breaks on native: API URLs, Google Auth, Firestore persistence, service worker, camera input, and CORS. Add native plugins for a polished iOS experience. Polish UI inconsistencies across all components.

## Technical Approach

### Architecture Decisions

**Platform detection:** Runtime via `Capacitor.isNativePlatform()` from `@capacitor/core`. One codebase, one build output, conditional behavior at runtime. The only build-time split is the PWA plugin (disabled for native builds via `CAPACITOR_BUILD=true` env var).

**API routing on native:** Enable `CapacitorHttp` plugin in capacitor.config.ts, which patches `fetch()` to route through native HTTP, bypassing CORS entirely. Also update API proxy URLs to absolute (`https://2manybeans.vercel.app/api/*`) on native via a shared `apiBase.js` module. Add CORS headers to API proxies as defense-in-depth.

**Google Sign-In on native:** Use `@codetrix-studio/capacitor-google-auth` plugin for native Google Sign-In dialog, then link the credential to Firebase via `signInWithCredential`. The existing web `signInWithPopup` flow stays untouched.

**Firestore persistence:** Switch to `persistentSingleTabManager` on native (WKWebView is single-tab). Detect platform at module init time.

const signIn = async () => {
  if (Capacitor.isNativePlatform()) {
    const { GoogleAuth } = await import('@codetrix-studio/capacitor-google-auth');
    const result = await GoogleAuth.signIn();
    const credential = GoogleAuthProvider.credential(result.authentication.idToken);
    await signInWithCredential(auth, credential);
  } else {
    await signInWithPopup(auth, googleProvider);
  }
};

## Scope Boundaries (Non-Goals for v1)

- **No push notifications.** Adds complexity (APNs setup, server-side), defer to v2.
- **No live updates (Capgo/Appflow).** Accept App Store review cycle for now.
- **No deep linking.** No router exists, no URL paths to link to.
- **No Android.** iOS only for v1.
- **No self-hosted fonts.** Google Fonts via CDN is fine for v1 (cached after first load).
- **No API proxy authentication.** Personal app, low abuse risk. Revisit if distributed.

## System-Wide Impact

### API Surface Parity
All four API proxies need identical CORS treatment. The `apiBase.js` module centralizes the URL resolution so all client-side helpers behave consistently.

### Error Propagation
On native, network errors from API proxies now include CORS-related failures as a new error class. The existing retry logic in `callClaude` and `callOpenAI` handles transient errors (429, 503) but not CORS failures. With CapacitorHttp enabled, CORS is bypassed entirely, so this risk is mitigated.

### State Lifecycle
Background/resume on iOS suspends JavaScript. In-progress API calls (tasting chat, bean scan) may time out. The existing retry logic will handle most cases. No new state persistence risks since Firestore handles all data.

### Integration Test Scenarios
1. Sign in on native, verify Firestore data syncs, sign in on web with same account, verify data is consistent
2. Start a bean scan on native, background the app mid-scan, resume, verify the scan completes or fails gracefully
3. Build for web with `npm run build`, verify PWA still works with service worker
4. Build for native with `npm run build:ios`, verify no service worker is registered

## Risk Analysis & Mitigation

| Risk | Likelihood | Impact | Mitigation |
|---|---|---|---|
| App Store 4.2 rejection (web wrapper) | Medium | High | Native camera, haptics, offline-first. Emphasize in review notes. |
| Google Sign-In setup complexity | Medium | High | Follow exact steps: Cloud Console iOS client, GoogleService-Info.plist, URL Scheme. Test on simulator first. |
| CapacitorHttp breaks image uploads | Low | Medium | Image data is sent as base64 in JSON (not FormData). If issues arise, fall back to standard fetch + CORS headers. |
| Service worker ships in native build | Low | High | Build-time flag `CAPACITOR_BUILD=true` conditionally excludes PWA plugin. Verify in build output. |
| Safe area CSS looks wrong on some devices | Low | Medium | Already using `env(safe-area-inset-*)`. Test on multiple simulator sizes. |

## Implementation Order

Phases 1-4 are the critical path (app won't work without them). Phase 5-6 can be parallelized. Phase 7 requires all others complete.

```
Phase 1 (Foundation) ─┬─> Phase 2 (API) ──> Phase 3 (Auth) ──> Phase 7 (App Store)
                       │
                       └─> Phase 4 (Firebase)
                       │
                       └─> Phase 5 (Plugins) ──> Phase 6 (UX Polish)
```
