# Coffee Hub — Lessons

Lessons learned during development. Review at the start of each session.

Format: `- **[Topic]**: [What went wrong] → [What to do instead]`

- **[WKWebView IndexedDB]**: IndexedDB is unreliable in Capacitor WKWebView. It causes Firebase Auth persistence and Firestore persistent cache to hang silently. → Use `initializeAuth` with `browserLocalPersistence` (localStorage) on native. Use empty `{}` Firestore settings on native (no persistent cache).
- **[WKWebView WebSockets]**: Firestore `onSnapshot` real-time listeners (WebSocket-based) are unreliable in WKWebView, causing "Loading" hang on app reopen. → Use `getDocs` (HTTP fetch) on native with polling interval. Keep `onSnapshot` for web only.
- **[Firebase Auth WKWebView]**: `getRedirectResult(auth)` triggers iframe setup to authDomain which interferes with WKWebView auth state. → Skip it on native with `Capacitor.isNativePlatform()` check. Always add a 3s safety timeout on `onAuthStateChanged`.
- **[Capacitor Google Sign-In]**: `@codetrix-studio/capacitor-google-auth` has no Package.swift and is incompatible with Capacitor 8 (SPM). The "plugin is not implemented on iOS" error means no native code was compiled. → Use `@capgo/capacitor-social-login` instead. Always check cap sync output for "does not have a Package.swift" warnings.
- **[Google OAuth Client IDs]**: Native Google Sign-In needs THREE client IDs: `iOSClientId` (from GoogleService-Info.plist), `webClientId` (from Google Cloud Console, type "Web application"), and `iOSServerClientId` (same as webClientId). The `serverClientId` in capacitor.config must be the WEB client ID, not the iOS one. Find them at Google Cloud Console > APIs & Services > Credentials > OAuth 2.0 Client IDs.
- **[iOS cap sync staleness]**: `cap sync` copies web assets + config to `ios/App/App/`. If you edit source files AFTER cap sync, the iOS bundle is stale. → Always verify iOS bundle timestamps and content match your latest changes before archiving. Run cap sync AFTER all code changes.
- **[Xcode SPM packages]**: After changing Capacitor plugins (npm install/uninstall), Xcode may cache old SPM packages. → Do File > Packages > Reset Package Caches, then Resolve Package Versions, then Clean Build Folder before archiving.
- **[GoogleService-Info.plist in Xcode]**: The file must be added to the Xcode project via GUI (right-click > Add Files > target checked), not just exist on disk. Without this, the file isn't bundled into the app.
- **[Capgo OTA interference]**: Capgo autoUpdate can download and apply an older JS bundle on app reopen, overwriting TestFlight fixes. → Disable autoUpdate during debugging. Only re-enable after the base app is stable.
- **[Capgo/TestFlight version sync]**: If a TestFlight build has newer JS than the latest Capgo bundle, Capgo will DOWNGRADE the app on next launch, reverting features. This looks like a mysterious regression. → ALWAYS upload a matching Capgo bundle immediately after any TestFlight build. The deploy sequence is: (1) build, (2) Capgo upload, (3) TestFlight archive. Never ship a TestFlight build without a corresponding Capgo bundle at the same or newer version.
- **[TestFlight build numbers]**: Apple rejects duplicate build numbers. Bump CURRENT_PROJECT_VERSION in project.pbxproj before each upload.
- **[Apple Developer new account]**: New accounts need: (1) accept agreements on developer.apple.com, (2) register a device (plug in iPhone), (3) create app record in App Store Connect, (4) answer export compliance for each build.
- **[Xcode DerivedData]**: Never delete DerivedData to "fix" issues, it wipes SPM packages and causes "No such module" build failures → Use `Product > Clean Build Folder` (Cmd+Shift+K) instead
- **[Capacitor Node Version]**: Capacitor 8 requires Node 22+. Use `nvm alias default 22` to make it permanent.
- **[Debug before deploy]**: Never tell the user a fix works without verifying. Add visible debug alerts, check bundle contents, verify timestamps. Guessing wastes hours.
- **[fetch() data URLs in WKWebView]**: `fetch('data:image/png;base64,...')` does NOT work reliably in iOS WKWebView. Use `atob()` + `Uint8Array` + `new Blob()` instead. This silently breaks any base64-to-Blob conversion on iOS native.
- **[Modal keyboard on iOS]**: Capacitor `resize: 'body'` shrinks the body but `position: fixed` elements still fill the full viewport. Adjusting `maxHeight` shrinks from the top but leaves the bottom behind the keyboard. Fix: adjust the container's `bottom` inset to push the entire modal above the keyboard.
- **[iOS Camera plist permissions]**: Capacitor Camera plugin requires ALL THREE plist keys: `NSCameraUsageDescription`, `NSPhotoLibraryUsageDescription`, AND `NSPhotoLibraryAddUsageDescription`. Missing any one causes a runtime rejection with a clear error message. Also add explicit `Camera.checkPermissions()` + `Camera.requestPermissions()` before `Camera.getPhoto()` calls.

- **Vite scaffold in non-empty dir**: `npm create vite@latest .` fails if dir has files → use temp dir approach (scaffold elsewhere, copy files over)
- **Trailing space in dir name**: The project folder has a trailing space in its name. This breaks many shell commands when paths aren't properly quoted. Always wrap paths in double quotes.
- **PRD vs Prototype scoring**: PRD recommendation scoring is wrong. Prototype scoring is the source of truth — uses different values, prefers smaller bags, checks origin/process (not roaster), and penalizes degassing.
- **React 19 from Vite**: Vite's latest React template uses React 19, not 18. This is fine and works with Firebase SDK v12.
- **Firebase SDK v12 persistence**: Uses `initializeFirestore()` with `persistentLocalCache({ tabManager: persistentMultipleTabManager() })`. NOT the old `enableMultiTabIndexedDbPersistence()`.
- **Use `vercel dev` for local dev**: The serverless proxy (`api/claude.js`) only works via Vercel's dev server, not plain `npm run dev`.
- **Vercel env vars with `echo`**: `echo "value" | vercel env add` appends a trailing newline (`%0A` in URLs). Use `printf` instead: `printf '%s' "value" | vercel env add VAR production`.
- **iOS standalone PWA sign-in**: `signInWithRedirect` does NOT work in iOS standalone PWAs — the redirect completes in a separate browser context that can't pass auth state back to the standalone app. Use `signInWithPopup` instead — on iOS 16.4+ it opens an in-app browser sheet that properly returns the auth result to the calling app.
- **NEVER delete user data as a workaround**: When Fellow device was full (14 profiles), the code deleted the user's last profile to make room. This destroys profiles the user is actively using. Always fail gracefully with a clear error message instead of taking destructive shortcuts.
- **NEVER auto-run destructive database operations**: Wrote a dedup function that deleted Firestore documents automatically on app load — it kept arbitrary copies and wiped out all of the user's manual edits (grind sizes, added beans, status changes). Destructive ops must NEVER run automatically. Always: (1) require explicit user action, (2) show a preview of what will be deleted, (3) confirm before executing. Prevent duplicates at the source (idempotent writes, disabled buttons) rather than cleaning up after.
- **When deduplicating, keep the most-edited copy**: The dedup kept whichever doc had the alphabetically-first Firestore ID, not the one with actual user edits. If dedup is ever needed, compare `updatedAt` timestamps and keep the most recently modified document.
- **Proxy swallowing API errors**: The `/api/claude` proxy caught all errors and returned a generic `500` with "Failed to call Claude API" — made debugging impossible. The real error was `529 Overloaded`. → Always forward the actual status code and error message from upstream APIs. Don't mask errors behind generic responses.
- **No model fallback = total outage**: When `claude-sonnet-4-20250514` was overloaded (529), every AI feature failed with no recourse. → Add a fallback model (Haiku) for 429/529 errors so the app degrades gracefully instead of breaking completely.
- **Test the deployed proxy, not just the code**: Spent time reading code looking for bugs when a simple `curl` to the production endpoint would have revealed the real error immediately. → When debugging API errors, hit the actual endpoint first to see the real error before diving into code.
- **BeanCard icon buttons must stay compact**: Code reviews and "iOS polish" passes keep adding `minWidth: 44` and extra padding to the icon buttons (learn, freeze, edit) in BeanCard.jsx. This steals horizontal space from the bean title, causing it to wrap onto too many lines. → NEVER add minWidth/minHeight to these buttons. Keep padding at 2px (learn) and 4px (freeze/edit). The compact sizing is intentional.
- **One Firestore write per handler**: Never call `updatePreferences()` twice in the same handler (e.g., once for grinder, once for grinderCustomName). Merge into a single call with a combined object. Same for `writeBatch` + `updatePreferences` on the same field.
- **writeBatch for multi-document consistency**: When writing to 2+ Firestore documents that must stay in sync (profile + emailList, preferences + beans), always use `writeBatch`. Separate writes = data inconsistency on partial failure.
- **Stabilize context object references**: `profile?.preferences || DEFAULT` creates a new reference every render, causing cascade re-renders in all context consumers. Use `useRef` + `JSON.stringify` deep-compare to return the same reference when values haven't changed.
- **Capgo OTA: verify on device, not CLI**: `npx @capgo/cli probe` confirms availability but not application. If update doesn't appear after 2 restarts, fall back to cap sync + TestFlight. Never tell user "it's live" from CLI output alone.
- **Modal overlay consistency**: All modals must use warm brown `rgba(44,24,16,0.4)` + `backdropFilter: blur(4px)`. Never use `rgba(0,0,0,...)`. Check Modal.jsx for the canonical pattern.
- **PWA workbox precache limit**: Images > 2MB silently fail to cache. Set `maximumFileSizeToCacheInBytes` in vite.config.js or compress images before adding to `public/`.
- **Sanitize at the source, not the call site**: When extracting shared functions (like `buildBeanDescription`), put sanitization inside the shared function. Call-site sanitization is fragile because new callers won't know to add it.
- **Always wrap JSON.parse on LLM output**: GPT/Claude regularly produce malformed JSON. Every `JSON.parse` on LLM output needs try/catch with a user-friendly error message.
- **System prompt injection is higher impact**: User-controlled strings in system prompts (like `grinderCustomName`) must be sanitized. System prompt injection can override model behavior more effectively than user message injection.
- **R13 Paywall mascot (TODO: restore)**: `ruphus-confident.mp4` was meant to peek above the PaywallSheet (240px MascotStage, per design handoff). Current implementation ran it full-bleed behind the sheet where it was never visible, then flashed for 500ms on dismiss (looked like a glitch). Removed for launch. To restore: use the "sheet variant" layout from `design_handoff_onboarding_redesign/README.md` (lines 257-303), show Ruphus in a MascotStage above the pricing cards, not behind the PaywallSheet.
- **Generated icon backgrounds must be transparent**: Image generation models (Gemini/nano-banana-pro) produce PNGs with solid white backgrounds by default. These show as visible white squares when placed on the app's cream/oat background. Always post-process generated icons with THREE steps: (1) threshold light pixels (brightness > 180) to transparent, (2) crop 8% from all edges to remove AI-drawn borders/frames, (3) auto-crop to content bounding box and re-center on transparent canvas. AI models frequently draw thin rectangular borders into icon images even when told not to. The threshold must be aggressive (180, not 240) because generated images have off-white backgrounds (~212 brightness). In future prompts, always include "No border, no frame, no rectangular outline around the icon." Apply this to ALL generated icons (nav, utility, brew method, jar) before deploying.
- **WKWebView: native horizontal scroll fails inside a 3D-flipped card face**: A `overflow-x:auto` scroll-snap row that worked on a flat surface would NOT scroll when nested inside the BeanDetailCard's `transformStyle:preserve-3d` + `backface-visibility:hidden` front face on iOS (the back face scrolled only because it sat inside an `overflow-y:auto` parent). Fix: use framer-motion `drag="x"` with `dragConstraints={ref}` (pure transform) instead of native scroll for overflow rails inside flipped/3D cards. Verified working via standalone harness.
- **Self-verify card components without auth/device via a standalone Playwright harness**: BeanDetailCard reads real Firebase user data, and synthesized sim taps don't reach the WKWebView's React handlers, so neither the device nor the iOS sim let me open/inspect the card autonomously. Solution: a temp `_harness.html` + `_harness.jsx` that mounts the component wrapped in `UserPreferencesProvider` with a mock bean (matching `LOCAL_BAG_OVERRIDES` so the override bag renders), served by `vite --port 51xx`, screenshotted with Playwright (viewport 402x874, deviceScaleFactor 3). Parametrize via URL query (e.g. `?notes=...`) to test edge cases (6+ notes drag rail, long names, missing fields). Delete the `_*.html/_*.jsx/_*.mjs` temps before committing.
- **Product-shot bag PNGs have baked-in whitespace + cast shadow**: The "transparent" bag images were 1024² squares with the bag filling only ~65% on opaque cream (rgb ~250,242,230), plus a soft cast shadow. Displaying them left dead space and (when color-cropped naively) the shadow shifted the bag off-center so it clipped the card frame. Fix: (1) strip cream→transparent by color-distance with feather, (2) compute the tight bbox of SOLID pixels only (`alpha>160`, excludes the soft shadow) and crop to it, (3) verify by compositing on the card's PAPER bg. Back up the original first (`docs/data/bag-backups/`). Apply the same to production bags at rollout.
- **framer-motion `animate` does NOT run inside a `createPortal`-to-body overlay in WKWebView; never gate visibility on it**: The tasting wizard mounted but showed "nothing"/blank on the real iOS dev app. Confirmed on-device: EVERY framer entrance animation in the portal was dead — overlay (`<m.div initial opacity:0 animate opacity:1>`), the step Stage, Ruphus mascot+bubble, AxisSlider notch word, FlavorWheelPicker drawer, and the header progress bar (stuck at default scaleX:1 = FULL because its animate→0 never ran). Every `initial={{opacity:0}}` stayed at 0 = invisible. `whileTap` (interaction) still works; only mount/`animate` is dead. Tells: blank where a fade-in belongs; a progress/fill bar stuck FULL. Fix: render visibility-critical content as plain DOM, visible by DEFAULT (opacity:1), use CSS keyframes (`.wiz-overlay-in`/`.wiz-stage-in`/`.wiz-pop`/`.ruphus-float` in global.css) as SAFE enhancements that degrade to instantly-visible; set transforms (progress scaleX) directly via `style`; drop `AnimatePresence mode="wait"` (it gates the next page on an exit anim that never completes). Rule: CSS for entrance/visibility, framer only for interaction. **Canvas rAF (RadarLightSweep) works fine in WKWebView** — the failure is framer-specific.
- **To test the REAL Capacitor app on the sim, point the WebView at a live vite server** — this is how the wizard bug was finally seen + fixed. The sim won't reliably run a local *bundled* build: Capgo serves `builtin`/OTA and unconditional on-screen DIAG markers never rendered even though confirmed in the installed `.app`. Instead set `server: { url: 'http://localhost:5173', cleartext: true }` + `CapacitorUpdater.autoUpdate:false` in `ios/App/App/capacitor.config.json`, run `vite --host`, `build-and-run`; the WebView loads live code with **HMR** so you iterate with screenshots and no rebuilds. Enter demo mode (Explore without an account) to skip Google auth; a temp `useEffect(()=>setWizardOpen(true),[beans.length])` auto-opens a flow without fighting flaky sim taps. Revert `server.url` after. (Playwright WebKit — `npx playwright install webkit` — is the same engine for fast harness repro, but the sim-from-vite is the truest "real app" test.)
